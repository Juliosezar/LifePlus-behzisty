## Step-by-step

### 1. Update `reports/agent.py` - Add `generate_report(case_data, user_input)` function

Build a function that:
- Takes structured case data dict (all DB fields serialized) + user free-text input
- Constructs a detailed Persian prompt with:
  - **System instruction**: Tells the LLM to write a formal visit report in Persian, following the exact structure of the examples
  - **Case data section**: All relevant DB fields (name, national ID, DOB, education, disability, family, housing, insurance, income, services provided, visits, demands, etc.)
  - **User observations section**: The free-text user input (problems, strengths, weaknesses, action plan)
- Calls the LLM via `ChatOpenAI` (same pattern as `ai_chat/agent.py`)
- Returns the generated report text

The prompt structure (derived from the 6 examples):
```
بخش اول: اطلاعات هویتی (from DB)
بخش دوم: وضعیت اجتماعی (derived from DB: disability, education, marriage)
بخش سوم: وضعیت خانوادگی (from DB: family members, dependents)
بخش چهارم: وضعیت اقتصادی (from DB: job, pension, insurance, housing)
بخش پنجم: اقدامات انجام شده (from DB: services_provided)
بخش ششم: مشکلات (from user input)
بخش هفتم: نقاط قوت (from user input)
بخش هشتم: نقاط ضعف (from user input)
بخش نهم: برنامه اقدام و پیشنهادات (from user input)
```

### 2. Update `reports/views.py` - Add `GenerateReportView`

- **GET**: Render the report generator page with the case info
- **POST (AJAX)**: Receive `extra_details` from user, serialize the case + related data into a dict, call `generate_report()`, return JSON with the generated text
- Decorator: `LoginRequiredMixin`
- Serialization helper: A method that converts a `Case` instance + its related objects (family, disabilities, reasons, recovered_reasons, visits, demands, services_provided, notes) into a clean dict for the prompt

### 3. Update `reports/urls.py`

Add: `path('case/<int:pk>/generate-report/', views.GenerateReportView.as_view(), name='generate_report')`

### 4. Create `templates/reports/generate_report.html`

Layout (RTL, Tailwind, matching existing style):
- **Header**: Case name + back button to case detail
- **Case summary card**: Display key info from DB (read-only, so user can reference it)
- **Textarea**: For user to type extra observations (problems, strengths, weaknesses, action plan)
- **Generate button**: Sends AJAX POST to the view, shows loading spinner
- **Rich text area**: A `<textarea>` (or contenteditable div) to display and edit the generated report
- **Copy button**: Copies the editor content to clipboard

The page uses a single AJAX call - no page reload needed. The generate button is disabled during the API call with a loading indicator.

### 5. Update `templates/cases/case_detail.html`

Add a "generate report" button in the header buttons area (next to edit/back buttons), linking to `reports:generate_report` for the case.

## AI Prompt Design (in `reports/agent.py`)

The prompt will instruct the LLM to:
1. Write in formal Persian (official government report style)
2. Follow the exact section structure from the examples
3. Use the DB data to populate factual sections naturally in prose (not as a table)
4. Integrate user-provided observations into the problems/strengths/weaknesses/action plan sections
5. Keep the tone professional and consistent with social work reporting standards
6. Use numbers for lists (1-, 2-, 3-)
